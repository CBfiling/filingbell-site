Alert ledger

A public record of every alert FilingBell sends, published so that past alerts can't be quietly edited, removed or back-dated.

How it works

Each time the daily alerts go out, FilingBell writes one ledger record. It lists every alert sent in that batch, with nothing left out, and for each one gives:

  • the SEC accession number, form type and filing date, with a link to the filing on EDGAR;
  • accepted_at: when the SEC accepted the filing, which is when it became public;
  • first_seen_at: when FilingBell first downloaded it;
  • sent_at: when the alert went out;
  • the label and strength FilingBell gave it.

The record is saved as compact JSON and fingerprinted with SHA-256. Each record also contains the fingerprint of the record before it, so the records form a chain: changing anything in an old record changes its fingerprint, which no longer matches the next record, and so on to the end. Days with no alerts get a record too, so gaps are visible.

Every record is published below exactly as it was hashed, and this site's source repository on GitHub keeps the history of when each file first appeared.

Check it yourself

  1. Download a record, for example ledger/1.json, and compute its SHA-256 (on macOS or Linux: shasum -a 256 FILE; on Windows: certutil -hashfile FILE SHA256). It must equal the fingerprint listed for it.
  2. Open the record: its prev_sha256 must equal the fingerprint of the record before it.
  3. Or check the whole chain at once with scripts/verify_ledger.py, which reads ledger/index.json and every record.
